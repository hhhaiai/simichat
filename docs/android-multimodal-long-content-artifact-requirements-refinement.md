## 1. 补充目的与优先级

主 PRD 已定义六类多模态任务、超长文本处理和 Artifact MVP 的总体范围。本规格补齐实施时容易产生歧义的产品判定，使“有入口”“有领域对象”“mock 通过”和“用户可完成任务”不再被混为一谈。

发生冲突时，按以下优先级处理：

1. 运行时真实行为、网络请求和真机观察；
2. 根目录 AGENTS.md 的当前进度、待办和验证账本；
3. 本补充规格；
4. 执行型 PRD；
5. 旧版多模态需求、历史实现说明或注释。

本轮明确不以新增音乐生成为验收项，不将未声明能力的渠道猜测为兼容 OpenAI，不把本地 mock、假 Adapter、页面入口或安装启动证据描述为真实云端任务成功。

## 2. 统一完成定义与阶段退出门槛

### 2.1 用户可用的完成定义

一个功能只有同时满足下列条件才可标记为“已完成”：

| 层级 | 必须满足的证据 |
| --- | --- |
| 产品层 | 用户可从明确入口完成一次任务，得到成功、失败、取消或可重试中的一种可解释结果。 |
| 交互层 | 文本、附件、参数、模型切换和任务状态遵守本规格，失败或取消不丢失未消费输入。 |
| 领域层 | 一次提交产生不可变 Options 快照；能力校验、请求映射、状态转换和结果交付有明确边界。 |
| 持久化层 | 重启后可恢复真实任务状态、已提交结果和必要草稿；不能把未知状态显示为成功。 |
| 协议层 | 以 mock HTTP 或等价请求捕获精确断言字段、附件编码、错误分类和降级次数。 |
| 质量层 | 新增单元或 Widget 测试、相关集成测试、静态分析和差异检查均通过，或单独记录既有基线问题。 |
| 真机层 | 需要系统文件、键盘、媒体播放、下载、后台恢复或 WebView 的能力，在 Pixel 8 给出实际观察证据。 |

以下情况均只能写为“基础已落地”或“部分完成”，不得写为功能完成：

- 只新增了菜单或面板；
- 只新增了数据类、Provider 或 Adapter；
- 只在内存数据库、fake service 或 mock 网络中通过；
- 只完成构建、安装或启动；
- 只完成单个模型或单个 happy path；
- 真实请求成功但没有保证结果写入、失败恢复或草稿保留。

### 2.2 阶段退出门槛

| 阶段 | 允许标记完成的条件 |
| --- | --- |
| Phase 1 能力与适配 | 六类 Options、三态能力、文件 transport、请求校验和 provider 映射均有单元测试；图片数量和多参考图不再被截断；xAI/Grok 视频使用 duration。 |
| Phase 2 超长内容 | 大粘贴归档、跨进程草稿、原生文件传输、文本降级、可恢复分批任务和工作视图均可用；不只完成阈值与切块器。 |
| Phase 3 聊天壳层 | 抽屉、聊天/工作切换、Composer 唯一主操作、键盘避让和下一条草稿并存规则均在手机真机可观察。 |
| Phase 4 六项任务面板 | 每个面板均连入能力校验、请求 Adapter、任务状态、结果交付、失败草稿恢复与对应 mock HTTP 测试。 |
| Phase 5 Artifact MVP | 结构校验、私有持久化、卡片、受限预览、源码、下载、版本和恢复均可用；WebView 安全测试和真机预览通过。 |
| Phase 6 真机验收 | 本规格第 10 节的 Pixel 8 矩阵全部完成；真实计费渠道仅在已配置测试账号时执行，其他项不得伪造成功结论。 |

## 3. 聊天、工作与 Composer 信息架构

### 3.1 顶层固定结构

聊天页面保持如下稳定层级：

~~~text
[菜单]                   [聊天 | 工作]                   [更多]
消息或工作内容
附件草稿区
单一 Composer
~~~

- 菜单打开会话抽屉，负责一级导航、搜索、置顶、最近会话、设置和新建会话。
- 聊天显示普通消息、用户附件、多模态最终结果和 Artifact 卡片。
- 工作只显示当前会话的任务清单、阶段、进度、错误、停止与重试；绝不显示模型隐藏推理、原始密钥、完整附件内容或本机绝对路径。
- 更多只提供当前视图的轻量动作。新建、设置、模型、停止和重试不得无边界堆入顶栏。
- 切换聊天/工作只切换视图，不改变会话、模型、草稿、附件、音频播放和运行中的任务。

### 3.2 Composer 唯一主操作状态机

最右侧主操作始终只有一个，状态优先级由高到低如下：

| 条件 | 主操作 | 点击结果 |
| --- | --- | --- |
| 当前会话有可停止的前台任务 | 停止 | 仅取消当前任务请求、轮询或后续分批；保留任务源数据。 |
| 实时语音面板处于连接或回答状态 | 实时语音对应的停止/断开 | 只结束实时会话。 |
| 当前草稿含文本或附件，且不在面板提交中 | 发送 | 发送普通聊天，或提交当前确认的工具任务。 |
| 其余情况 | 录音或实时语音入口 | 打开既有录音或实时语音流程。 |

- 有附件但没有文本时，普通发送仍可用；工具面板可另行要求必填提示词或输入内容。
- 任务运行中，用户可以继续编辑下一条普通草稿；下一条草稿必须与已提交任务快照隔离。
- 停止只作用于用户明确选择的任务。若同时存在多个任务，默认停止当前工作卡片中被选中的任务；没有选中时显示任务选择，而不是猜测取消全部。
- 成功只清理任务提交时明确标记为 consumed 的文本、附件和面板参数。此后用户编辑的内容不得被清理。
- 任务运行期间再次点击同一任务的提交按钮必须被幂等拦截，并将焦点定位到已有工作卡片。

### 3.3 工作列表规则

工作视图默认按以下顺序展示：

1. 当前运行中的任务，按最近状态更新时间倒序；
2. 等待上传、排队和可恢复任务，按创建时间升序；
3. 最近失败、取消和成功任务，按更新时间倒序；
4. 已成功且已交付的历史任务默认折叠，保留“查看已完成”入口。

工作卡片必须显示任务类型、发起会话、当前阶段、已完成/总数、可安全展示的错误摘要、开始时间和操作。无进度总量时显示明确阶段文字，不得伪造百分比。

## 4. 设置默认值、一次性 Options 与能力数据的边界

### 4.1 三类数据不可混写

| 数据类别 | 保存位置与生命周期 | 允许变化 |
| --- | --- | --- |
| 设置默认值 | 渠道或模型配置及本地偏好 | 只在用户主动“设为默认值”或设置页保存时改变。 |
| 本次 Options | 任务草稿和已提交任务的 requestSnapshot | 面板中可编辑；提交后不可原地改写，重试须产生新尝试或明确替换快照。 |
| ModelCapabilities | 内置 registry、渠道覆盖和模型 profile | 由产品配置、渠道管理员或用户显式覆盖；不得由一次任务参数推断并保存。 |

- 打开面板时，以当前选中模型的默认值预填本次 Options。
- 面板内改动不回写设置默认值；“设为默认值”必须为显式操作并显示成功反馈。
- 设置页之后改动默认值，不回写已经打开或已经提交的任务 Options。
- 任务历史展示时读取提交快照，而不是读取今天的默认值或当前模型能力。

### 4.2 模型切换的逐字段处理

用户在面板中切换模型后，对每个字段按照下表处理：

| 目标能力 | 现有值 | 面板行为 |
| --- | --- | --- |
| supported 且值合法 | 保留 | 继续显示。 |
| supported 但值不在新能力范围 | 重置为新模型默认值 | 显示一次“已按新模型能力调整”的字段级提示。 |
| unsupported | 清空且禁用 | 显示该模型不支持的原因；不得序列化旧值。 |
| unknown，且字段不是安全基础字段 | 清空或保持未指定 | 显示“模型未声明此能力，未发送该参数”。 |
| unknown，且字段是安全基础字段 | 可保留 | 仍应在 Adapter 层只发送 profile 明确允许的字段。 |

“未知”绝不等价于“支持”。在模型能力未知时，图片的 prompt/数量 1、TTS 的文本、STT 的音频和视频的 prompt 可作为基础字段；比例、清晰度、像素分辨率、质量、多个结果、参考素材、特殊输出格式、时长等高级字段必须保守不发，除非 profile 显式允许。

## 5. 六项任务面板的可执行细则

所有任务在点击提交前必须完成本地必填校验、能力校验、文件存在性校验、MIME/大小/数量校验和明确授权校验。校验失败时焦点定位到首个字段，保留全部草稿，不创建网络任务。

### 5.1 生成图片

字段顺序固定为：模型、提示词、数量、参考图、比例、清晰度、像素分辨率、质量、生成。

| 字段 | 默认和交互 | 提交规则 |
| --- | --- | --- |
| 模型 | 当前可用图片模型；自定义 ID 是带保守提示的高级入口 | 必填，必须有图片生成能力。 |
| 提示词 | 空；可以从 Composer 文本预填 | 去除纯空白后必填。 |
| 数量 | 模型默认数量；没有声明时固定为 1 | 必须在模型数量范围内，写入请求 n。 |
| 参考图 | 空；多图可排序、替换、删除 | 不能超过 maxReferenceImages；不得截断为第一张。 |
| 比例 | 自动/未指定优先；仅展示已声明选项 | 自动不序列化；指定值必须被 capability 支持。 |
| 清晰度 | 自动/未指定优先；示例为 1K、2K、4K | 自动不序列化；指定值必须被 `supportedResolutions` 支持，并写入 `resolution`。 |
| 像素分辨率 | 自动/未指定优先；示例为 1024x1024、1536x1024 | 自动不序列化；指定值必须被 `supportedSizes` 支持，并写入 `size`。 |
| 质量 | 自动/未指定优先 | 自动不序列化；指定值必须被 capability 支持。 |

成功交付必须把同一次图片任务的全部结果作为一个原子结果组写入一条 assistant 结果消息或一个统一结果卡片；全部文件归档与消息/附件事务完成后才标记 succeeded。任意一个结果文件归档失败时，不得留下“已完成”但缺图的半组结果；工作卡片应显示可重试失败。

### 5.2 语音合成

字段顺序固定为：模型、输入内容、音色、语速、输出格式、试听或生成。

- 输入内容是任务私有文本框，可从 Composer 预填；空白内容不得提交。
- 音色列表显示名称、语言和风格说明；未声明音色时不能伪造自由文本值。
- 语速默认 1.0x，取值范围由 profile 或 capability 确定。
- 输出格式优先使用模型默认格式；用户未指定时不发送自定义 response_format。
- 试听只用于临时播放，不写入消息、不创建成功任务结果、不覆盖上一段正式生成音频；试听失败也不清除任务草稿。
- 生成成功后写入当前会话的音频结果卡片，并显示格式、时长、文件大小、播放和下载动作。

### 5.3 声音设计

字段顺序固定为：模型、输入内容、声音风格、语速、输出格式、生成。

- 输入内容与声音风格均属于本次 Options；模型要求风格时，风格去除纯空白后必填。
- 声音风格是自然语言描述，不是全局 TTS 模式开关。
- 用户可以将当前风格显式保存为本地预设；保存预设不修改历史任务，也不自动改写其他面板。
- 若 profile 不支持声音设计，入口保持可见但禁用，并说明尚未配置或当前模型不支持的具体原因。
- 成功、失败、取消和重试语义与语音合成一致。

### 5.4 声音克隆

字段顺序固定为：模型、输入内容、参考音频、语速、输出格式、授权确认、生成。

- 参考音频支持上传、录制、试听、替换、删除，展示文件名、格式、大小和时长。
- 当前 Composer 的临时 audio 附件优先于设置页已归档参考音频；使用临时文件时，不得自动写回设置。
- 模型切换后若参考音频格式、时长或大小不再合法，必须移除该选择并提示重新选择。
- 每次提交都必须由用户勾选本次授权确认：“我确认拥有该声音的使用权，或已获得声音主体的明确授权。”
- 授权确认只保存为本次任务的布尔值和确认时间；不保存声音主体身份、声明全文或未脱敏音频内容到日志。
- 重试同一已提交任务时，若参考音频、模型或任务文本未变，可沿用该次确认；任一项变化后必须重新确认。
- 未确认、参考音频失效或文件不合规时不得创建网络任务。

### 5.5 识别语音

字段顺序固定为：模型、音频文件、识别语言、开始识别。

- 每次独立识别任务只消费一份音频；多份文件应创建多个草稿任务或要求用户选择，不得静默取第一份。
- 语言菜单始终含自动检测、中文、English。序列化规则固定：自动检测省略 language；中文发送 zh；English 发送 en。
- 识别成功后写入会话结果卡片，支持展开全文、复制、编辑、保存 txt、保存 md、重新识别、填入 Composer、基于结果继续提问。
- 选择“填入 Composer”时，将文本插入当前下一条草稿，不覆盖用户已输入内容；如果插入后触发大粘贴策略，走同一私有文本附件流程。
- 已有“附件发送后自动转写”可以继续存在，但不得替代本独立入口；两个路径应清楚标识来源，避免同一音频产生无解释的重复转写。

### 5.6 生成视频

字段顺序固定为：模型、提示词、首帧图、参考图、参考音频或参考音色、时长、比例、分辨率、生成。

| 字段 | 语义与规则 |
| --- | --- |
| 首帧图 | 仅一张，决定视频的首帧；只能在 supportsFirstFrame 时选择，单独序列化。 |
| 参考图 | 0 至 maxReferenceImages 张，用于视觉参考；可排序、替换、删除，不得与首帧图混装或截断。 |
| 参考音频 | 仅在 supportsReferenceAudio 时显示；上传、录制、试听、替换和删除均需走独立字段。 |
| 时长 | 从模型声明的离散秒数中选择；默认选择 profile 默认值或第一个可用值。 |
| 比例与分辨率 | 默认未指定；只显示模型已声明的选项，未指定时不发送。 |

视频任务若上游返回异步 job ID、轮询 URL、deadline 或取消端点，必须持久化，并在重启后根据真实状态恢复。xAI/Grok 将通用 duration、aspectRatio、resolution 映射为 duration、aspect_ratio、resolution；不得发送 seconds。提交前若 profile 不能承载首帧、多个参考图或参考音频，面板必须阻止提交，而不是静默丢弃素材。

## 6. 超长内容发送的三路径判定

### 6.1 发送决策表

普通消息和附件发送前，依次解析模型能力、渠道 transport、文件约束与有效输入预算。行为必须遵守下表：

| 输入和能力 | 处理路径 | 用户可见结果 |
| --- | --- | --- |
| 合法文件，fileInput 为 supported，存在合法 transport | A：原生文件发送 | 时间线保留文件卡片；工作卡片展示上传/发送阶段。 |
| 纯文本文件，fileInput 为 unsupported 或没有可用 transport，全文不超过有效输入预算 | B：仅网络层文本降级 | 时间线仍只显示附件卡片；请求中使用明确的附件边界包裹全文。 |
| 纯文本文件，不能原生发送，且全文超过有效输入预算 | C：可恢复分批任务 | 工作卡片显示准备、分块、处理和最终生成；中间结果不进入时间线。 |
| 纯文本文件，fileInput 为 unknown | 先按 B/C 的保守本地处理 | 不尝试猜测上传协议；提示“模型未声明文件输入能力，已按文本处理”。 |
| 非文本文件，fileInput 为 unsupported、unknown 或无合法 transport | 提交前拒绝 | 保留草稿，说明当前模型/渠道无法发送此类文件；不读取或伪装转换二进制文件。 |
| A 路径收到明确附件不支持错误 | 仅一次 A 到 B 或 C 降级 | 显示“当前渠道未接受附件，已改为文本处理”；同一 task 不得再次自动降级。 |
| A 路径收到认证、额度、超时、内容安全或未知 400 | 不自动降级 | 按错误分类显示并提供重试/改参数/切模型。 |

明确附件不支持错误仅包括 415、profile 已登记的 unsupported_file/unsupported_content_type/invalid_attachment 错误码，或已验证的等价错误摘要。不能将所有 400 视为附件不支持。

### 6.2 有效输入预算

在任何文本降级或分批前，计算：

~~~text
effectiveInputBudget =
  contextWindowTokens
  - systemPromptTokens
  - conversationHistoryTokens
  - toolDefinitionTokens
  - reservedOutputTokens
  - safetyMarginTokens
~~~

- safetyMarginTokens 必须不少于 contextWindowTokens 的 10%，并为序列化、语言差异、模型 token 估算误差和最终回答保留空间。
- 任一组成未知时使用保守上界或拒绝单次文本降级，不能按零处理。
- 若 effectiveInputBudget 小于最低可用值，提示用户缩短对话、切换更大上下文模型或启动分批，不发送必然超限的请求。
- 网络层文本包裹必须区分用户问题和附件内容，且附件正文不得被当作系统指令。附件内容只可作为明确标记的数据区。

### 6.3 大粘贴与草稿恢复

- 大粘贴命中阈值时，只替换本次插入 delta；已有 Composer 文本、光标前后内容和其他附件不得被吞掉。
- 私有文本附件保存原始 Unicode、换行、空行、Tab、Emoji、代码围栏、末尾换行、MIME、字符数、UTF-8 字节数、估算 Token、SHA-256、来源会话和草稿 ID。
- 应用被系统杀死后，当前会话草稿必须能恢复文本、附件顺序、重命名、待提交任务面板和大粘贴元数据；无法找到的私有文件显示“原草稿文件不可用，可删除或重新选择”，不得假装附件仍可发送。
- 预览、重命名、还原为文本和删除必须操作同一私有附件；删除成功后清理对应私有临时文件，仍被其他草稿或任务引用时延迟清理。

## 7. ChunkedContentTask：策略、状态、重试与恢复

### 7.1 分块和策略选择

切块优先保持语义边界：H1/H2、完整代码围栏、段落、行、句子、最后才进行 code-point 安全硬切。每个 TextChunk 必须具备 batchId、chunkIndex、totalChunks、sourceAttachmentId、startOffset、endOffset、text、estimatedTokens、sha256。

策略选择规则：

| 用户意图 | 策略 | 输出约束 |
| --- | --- | --- |
| 总结、问答、分析、提取、分类、检索 | mapReduce | 每块仅产生结构化中间结果；最终请求统一合成一条答案。 |
| 翻译、改写、润色、格式转换、按原文输出 | orderedTransform | 严格按 chunkIndex 处理和拼接；可做一次轻量一致性检查，但不得删段、重排或重复。 |
| 无法可靠分类 | mapReduce | 任务卡明确显示“按分析方式处理”；用户可取消后改用指定任务。 |

不得以启发式分类结果覆盖用户选择的显式模式。

### 7.2 持久化数据与状态

ChunkedContentTask 至少保存：

~~~text
id, conversationId, sourceMessageId, sourceAttachmentId,
originalPrompt, modelId, providerId, strategy,
requestSnapshot, totalChunks, completedChunks,
chunkResults, retryMetadata, finalResponseMessageId,
status, createdAt, updatedAt
~~~

状态转换限定为：

~~~text
draft -> validating -> preparing -> running -> succeeded
                                            -> failed
                                            -> cancelled
~~~

- preparing 仅完成本地分块和任务持久化，不得发送任意 chunk。
- running 时可显示 completedChunks/totalChunks；final reduce 或拼接阶段显示“正在生成最终回答”。
- succeeded 只能在最终回答、关联附件和任务交付引用事务完成后写入。
- failed 与 cancelled 保留原始附件、问题、Options、已完成 chunk 的安全内部缓存及可解释失败位置。
- 中间 chunk 输出不得写入普通消息、Markdown 对话档案或默认导出内容。

### 7.3 重试、取消和恢复

- 每个 chunk 最多自动重试 2 次；总尝试次数必须持久化，并复用已有网络瞬态错误分类。
- 认证、权限、模型不存在、内容策略拒绝、文件不支持和不可恢复参数错误不自动重试。
- 用户停止后应取消当前请求、停止尚未发送 chunk；不写入半条 assistant 最终消息。
- 用户可以选择“从头重试”或“继续未完成部分”。继续仅在任务、源附件、模型和 requestSnapshot 仍有效时可用；否则标为“需要重新提交”。
- 应用恢复时，正在运行但没有可用远端 resume 语义的任务不得标记为成功；应转为“已中断，可继续/重试”并显示最后完成 chunk 数。
- 相同 taskId 的恢复过程必须幂等：不能重复创建源消息、最终 assistant 消息、附件或 Artifact。
- 最终 reduce 失败时保存已完成的中间结果，让用户重试最终生成，而不是重新花费所有 chunk 请求；但只有当中间结果完整、来源未变且模型/profile 仍兼容时才允许。

## 8. Artifact MVP 的严格边界

### 8.1 创建、解析和回退

Artifact 只能通过下列明确来源创建：

1. 用户在 + 菜单选择“创建 Artifact”；
2. 当前模型支持结构化 Artifact 工具调用；
3. 模型返回符合规范的 JSON 或带明确 artifact 标记的 fenced envelope。

普通代码块、长文本和 Markdown 回答不得靠模糊猜测自动变成 Artifact。解析失败时，保留模型完整原文为普通消息，并提供“Artifact 数据格式无效，重新生成”操作。

ArtifactEnvelope 的最小字段为：

~~~text
title, type, entryFile, files[]
ArtifactFileInput: path, language, mimeType, content
~~~

MVP 支持 type：html、svg、mermaid、markdown、text、code、web_project。每个文件路径必须使用相对 POSIX 路径。

### 8.2 Envelope 合法性与路径规则

提交和解析时必须一次性校验：

| 规则 | 不满足时的结果 |
| --- | --- |
| title 非空，去除纯空白后长度合理 | 拒绝 envelope，回退普通消息。 |
| files 非空且每个 path 唯一 | 拒绝 envelope，不隐式覆盖重复文件。 |
| path 是相对 POSIX 路径 | 拒绝绝对路径、盘符、反斜杠路径和空路径。 |
| path 不含 . 或 .. 片段、NUL、控制字符 | 拒绝路径穿越和不可见危险路径。 |
| path 规范化后仍位于 Artifact 根目录 | 拒绝。 |
| entryFile 指向 files 中恰好一个文件 | 拒绝，不猜测入口。 |
| type 与 entryFile/MIME 合理匹配 | 拒绝或按普通代码回复，不以错误类型运行。 |
| 总文件数、单文件字节数、总解码字节数未超过 MVP 限制 | 拒绝并提示缩小成果。 |

MVP 的固定本地限制为：最多 64 个文件、单文件最多 1 MiB、总解码内容最多 8 MiB、单个 path 最多 240 个 Unicode code point。限制命中前优先在请求侧约束模型输出；解析侧仍必须再次校验。

### 8.3 预览矩阵

| 类型 | 手机端预览 | 源码 | 下载 | 备注 |
| --- | --- | --- | --- | --- |
| Markdown | 安全 Markdown 渲染 | 是 | .md | 禁止执行嵌入脚本。 |
| SVG | 图片或受限 SVG 预览 | 是 | .svg | 禁止脚本、外链与危险 URI。 |
| Mermaid | 现有安全渲染链路 | 是 | .mmd 或 .md | 失败时显示源码和错误。 |
| 单文件 HTML | 受限 WebView | 是 | .html | 见第 8.4 节。 |
| 静态 web_project | 入口存在时受限 WebView | 是 | .zip | 不在 Android 内编译。 |
| code/text | 代码/文本阅读器 | 是 | 对应扩展名 | 不自动执行。 |
| React/源码项目无构建产物 | 不预览 | 是 | .zip | 提示需要预构建 index.html。 |

手机竖屏使用全屏 Artifact 页面；平板或横屏宽度达到应用既有大屏断点时，可以使用会话左侧、Artifact 右侧的分栏。不得在窄屏强制双栏。

### 8.4 WebView 预览隔离

所有 HTML 或静态网页预览必须：

- 只从该 Artifact 版本的受控虚拟根加载，不能直接暴露 App 私有目录；
- 禁止 file 访问、content provider 访问、任意外部网络、下载自动发起和文件选择；
- 禁止摄像头、麦克风、定位、通知、剪贴板读取和高权限 JavaScript Bridge；
- 拦截外部链接、自定义 scheme、intent、支付和深链接；用户确认后才交给系统浏览器；
- 禁止网页覆盖宿主导航或静默跳转到外部应用；
- 显示加载、渲染错误、刷新和停止加载；
- 在版本切换或页面关闭时终止旧页面加载与脚本上下文。

若平台 WebView 无法可靠满足某项隔离要求，则该类型降级为源码预览与下载，不能带着权限缺口继续执行。

### 8.5 编辑、版本和下载

- 编辑始终基于当前已保存版本创建新草稿版本；保存成功后才提升 currentVersionId。
- “继续修改”请求只携带当前 Artifact 必要文件、用户修改说明和安全上下文，不无条件包含整个会话。
- 修改失败、解析失败或预览失败时，上一可用版本继续可打开、下载和恢复。
- 版本恢复创建一个新的版本记录，不覆盖历史版本；恢复后 currentVersionId 指向新记录。
- 下载永远导出当前已保存版本：单文件按类型扩展名保存，多文件生成规范化 ZIP。
- ZIP 生成前后均验证相对路径，禁止 ../、绝对路径、重复条目和链接逃逸；使用系统文件保存界面，不默认写入无权限公共目录。
- 删除 Artifact 需二次确认，并只影响本地 Artifact 数据与关联卡片，不删除原始普通聊天消息。

## 9. 数据、隐私、性能、无障碍与迁移

### 9.1 数据与隐私

- 大粘贴原文、音频、图片、视频、Artifact 文件和中间 chunk 结果默认只放 App 私有目录或现有受管理数据库。
- API Key、Bearer、完整 Base64、完整大粘贴、原始音频和本机绝对路径不得进入日志、错误摘要、任务列表、Markdown 档案、诊断导出或默认备份。
- 导出、同步或分享含附件、音频、Artifact 时必须显式显示范围并由用户确认；默认不把内部 chunk 结果、已取消任务缓存或原始授权素材打包。
- 任务 requestSnapshot 保存足够重试所需信息，但凭据只引用加密配置，不复制密钥明文。
- 删除任务、附件或 Artifact 后执行引用计数或延迟清理，避免删除仍被其它会话、草稿、版本或待恢复任务引用的私有文件。

### 9.2 性能与稳定性

- 大粘贴检测、SHA-256、Token 粗估、Markdown 判断、文件读写和分块不得阻塞 UI 帧；在必要时放到受控后台 isolate。
- 预览缩略图、音视频元数据和 Artifact 文件树采用懒加载；超大文件不得在列表页一次性读入内存。
- 所有任务重试、轮询、恢复和下载必须有取消句柄、超时、最大尝试次数和去重键。
- 任何任务状态变更、消息写入、附件写入和 Artifact 当前版本切换都必须定义原子边界；崩溃后要么可恢复、要么可重试，不能制造“已完成但文件不存在”的状态。
- 不为本功能新增无人管理的第二数据库；Drift schema 变更必须提供向前迁移、旧库测试和结构化备份兼容。

### 9.3 无障碍与移动端适配

- 支持项目既有 90% 至 120% 全局字号；120% 下字段标签、错误、按钮和结果卡片不得截断、溢出或遮挡。
- 所有可点击图标和主要操作的实际点击热区不小于 44 × 44 logical pixels。
- 任务进度、上传、失败和完成通过语义标签和可读文本表达，不能只依赖颜色、动效或图标。
- 面板打开时焦点进入标题或第一个无效字段；关闭后返回触发入口；错误后焦点定位到错误字段。
- 键盘打开、横屏、分屏和系统返回应保持草稿，不得让底部提交按钮被遮挡。

### 9.4 数据迁移与兼容

- 已有普通附件、现有 MediaJob 和旧 TTS/STT 配置继续按原语义可读；不能因新增 Options、TaskRecord 或 Artifact 表而丢失旧会话。
- 旧任务没有新字段时，用明确的 unknown/不可恢复状态表示，不能填造默认能力或显示为已完成。
- Schema 升级必须包含：旧数据库迁移测试、导出/导入往返测试、失败回滚或可恢复策略、任务去重与文件引用清理测试。
- 不手改 Drift 生成文件；迁移后按项目既有命令重新生成并提交必要生成结果。

### 10.2 Pixel 8 人工或自动化真机观察

| STT | 对同一音频分别选择 auto、中文、English | 语言请求按省略/zh/en 映射；结果卡片可复制、编辑和填入现有草稿。 |

| Artifact | 创建 HTML、SVG、Markdown 和无构建产物的源码项目 | 前三者按矩阵预览；源码项目只看源码/下载；外链、相机、麦克风、定位和 file 访问被拦截。 |
| 下载与版本 | 编辑 Artifact、保存、恢复旧版并下载多文件 ZIP | 恢复产生新版本；下载为当前已保存版本；ZIP 无路径穿越。 |

每项真机记录至少包括：设备标识、构建版本、开始条件、实际操作、实际观察、失败日志或截图路径、清理结果。未执行的项目在账本中直接列为“未验证”，不得由相近 mock 结果代替。

4. **已完成（2026-08-19）**：`TextChunker` 已接到持久化 `ChunkedContentTask`；已实现 `mapReduce`、`orderedTransform`、每段瞬态重试、Stop、冷启动中断收敛、继续/从头重试、唯一最终 assistant 与聊天内工作卡。后续仅补真实云端和 Pixel 8 长文本交互验收。
5. 收口聊天/工作/Composer 状态机和“下一条草稿”隔离规则。
