# 移动端 ChatGPT 风格交互基准

> **状态**：需求已确认，待实施。
> **最后更新**：2026-08-19。
> **适用范围**：移动端聊天主页、会话抽屉、工作模式和多模态 Composer。
> **参考边界**：用户提供的 ChatGPT 截图只用于提炼信息架构、操作层级和状态切换；不得复制 ChatGPT 品牌、图标、文案、头像、会话标题或视觉资源。

## 1. 目标

SimiAIChat 的移动端主路径采用“内容优先、单手可操作、底部输入始终可达”的 ChatGPT 式交互：

1. 用户从左上角菜单进入会话抽屉，在同一处搜索、打开置顶会话、打开最近会话和新建聊天。
2. 用户在主页面通过顶部的“聊天 / 工作”切换聊天和任务协作两种上下文，而不是将工具和设置散落在聊天流中。
3. 用户始终从底部单一 Composer 输入；附件、图片生成、语音、视频等能力由左侧 `+` 进入，不增加常驻复杂工具栏。
4. 发送、流式生成、停止和实时语音均在同一个底部操作位清晰切换，用户不需要寻找第二个停止入口。

## 2. 信息架构

### 2.1 会话抽屉

移动端点击左上角菜单后，从左侧推出全高抽屉；点击遮罩、按系统返回键或向左滑动可关闭。

抽屉顺序固定如下：

1. 顶部品牌标题 `SimiAIChat` 与会话搜索入口。
2. 一级导航：资料库、项目、插件、已计划、远程、更多。未实施的入口必须显示“即将支持”或进入已有的对应页面，不能展示无响应按钮。
3. `已置顶`：展示置顶文件夹和置顶会话；会话若有多个协作者或来源，可用最多两枚重叠小头像表示，不展示真实联系人数据。
4. `最近`：按最近消息时间倒序展示非置顶会话；仅显示单行标题，长标题省略。
5. 底部固定操作：设置入口和高对比度的“新建聊天”圆角主按钮。

抽屉内的会话点击后必须先切换会话、恢复该会话草稿，再自动关闭抽屉；“新建聊天”成功后同样关闭抽屉并将焦点交给 Composer。

### 2.2 顶部模式切换

聊天主页顶部采用紧凑、居中的分段控件：

```text
聊天 | 工作
```

- 默认进入“聊天”。
- `聊天`保留普通会话时间线、模型切换和多模态 Composer。
- `工作`进入当前会话绑定的任务协作视图；任务输入使用“与 SimiAIChat 协作”提示语，显示任务运行、思考、停止和完成状态。
- 左上角始终保留抽屉入口；右上角根据模式提供新建 / 编辑和更多操作，禁止把设置、重试、模型等所有动作同时堆在顶栏。
- 模式切换不得创建新会话、丢失当前输入、丢失附件草稿或中断非用户主动取消的媒体任务。

### 2.3 聊天与工作状态

| 状态 | 内容区 | 底部主动作 | 必须可见的反馈 |
| --- | --- | --- | --- |
| 空聊天 | 留出大面积空白，避免营销卡片抢占首屏 | `+`、文本输入、麦克风、实时语音 | 当前模式与输入提示 |
| 输入聚焦 | 键盘弹出，Composer 跟随键盘上沿 | `+`、文本输入、麦克风 / 实时语音；有文本后显示发送 | 不遮挡最后一条消息和附件预览 |
| 流式回复 | 消息流保持当前回复可见 | 发送位替换为停止 | “正在生成”或流式正文，停止后恢复发送 |
| 工作执行 | 显示任务步骤、工具状态和结果 | 发送位替换为停止 | “正在思考 / 正在执行 / 已完成 / 失败可重试” |
| 实时语音 | 打开独立实时语音面板，不伪装成文件录音 | 结束语音会话 | 连接、输入转写、助手转写和中断状态 |

## 3. 单一 Composer 交互

### 3.1 静止与输入状态

底部 Composer 为浅色圆角胶囊，固定在安全区域上方：

```text
[ + ]  询问 SimiAIChat                         [麦克风] [实时语音]
```

- 左侧 `+`：打开多模态工具菜单。
- 中间：多行文本输入，最多扩展到约四行；超过后内部滚动，不能无限推高消息流。
- 右侧麦克风：录音文件 → STT → 聊天路径；长按显示 `自动识别 / 中文 / English`。
- 最右实时语音：进入独立 Realtime 面板；未配置时显示明确原因，不静默失败。
- 文本非空时，最右实时语音位切换为发送按钮；流式或任务执行中切换为停止按钮。
- 附件预览显示在 Composer 上方，并保持删除、数量和大小反馈可达。

### 3.2 `+` 工具菜单

`+` 打开可滚动底部菜单，按“添加内容、语音与编辑、生成与工具”三组分区。所有工具在当前会话与当前草稿上下文中工作：

```text
添加内容：相机、相册、选择文件
语音与编辑：实时语音、编辑图片、识别语音
生成与工具：生成图片、生成视频、声音合成、声音设计、声音克隆、生成音乐、深度思考
```

菜单项的 disabled 状态必须保留入口并展示缺失原因，例如“当前模型不支持视频生成”或“请先配置 TTS”；不得在无配置时直接隐藏能力。已有“生成音乐”等入口可以保留，但 2026-08-19 当前实现批次不以新增音乐能力作为验收项；完整范围见 `docs/android-multimodal-long-content-artifact-prd.md`。

图片、声音和视频工具都应先打开本次任务的参数面板。模型、数量、参考素材、比例、清晰度、音色、风格、时长等均属于单次任务参数；设置页只保存厂商凭据、默认模型和默认值，不能要求用户为了每一次生成回到设置页切换全局模式。

### 3.3 任务成功与失败

- 成功：结果直接插入当前会话时间线；只清除已被该任务消费的文本和附件，未消费附件保留。
- 失败：保留文本、附件和已选参数，显示可理解的失败摘要与重试操作。
- 取消：不提交半条 assistant 消息，不丢失用户草稿。
- 后台恢复：恢复到会话后将可重试状态展示在消息流和 Composer，不能仅用一次性 Snackbar。

## 4. 视觉与动效约束

- 采用 SimiAIChat 自有品牌、颜色与图标；参考的是布局和行为，不是像素级复刻。
- 抽屉、分段控件、Composer 和底部菜单使用短、可中断的过渡动画；系统“减少动态效果”开启时应降低或取消位移动画。
- 所有可点击控件最小触达尺寸为 44 logical pixels；抽屉、键盘与底部安全区在 90%–120% 全局字体下不得遮挡主要操作。
- 消息、任务和媒体状态使用文字与图标双重表达，不能仅依赖颜色。
- 工作模式中的“正在思考”仅展示任务状态，不显示模型内部隐式推理文本。

## 5. 验收标准

1. Pixel 8 等 390–430 logical pixels 宽度设备上，抽屉、聊天 / 工作切换、键盘和 Composer 不发生横向溢出。
2. 打开抽屉后可以搜索、进入置顶 / 最近会话、新建聊天并自动关闭抽屉；会话草稿按会话隔离恢复。
3. 输入、流式、停止、媒体任务和实时语音五种状态下，底部主操作都清晰且只有一个有效“停止”路径。
4. 从 `+` 进入图片、语音、视频工具后，所有本次参数可在任务面板完成；返回或失败不丢失草稿。
5. 聊天 / 工作切换不改变当前会话、模型选择、未发送附件、播放状态或持久化媒体任务。
6. Widget 测试覆盖抽屉状态、模式切换、Composer 状态机、键盘避让、120% 字号、工具禁用原因和任务失败草稿恢复；Android 真机 smoke 覆盖抽屉 → 新聊天 → 输入 → 发送 / 停止主路径。
