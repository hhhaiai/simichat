# SimiChat 移动端多模态重构开发需求（Codex 执行版）

## 一、任务说明

请直接在现有 **SimiChat** 项目代码基础上完成移动端多模态界面重构。

本次任务不是制作静态 Demo，也不是重新创建一个独立项目，而是：

1. 阅读并理解现有项目结构、技术栈、路由、状态管理和接口调用方式。
2. 尽量复用现有组件、模型配置、接口封装和会话数据。
3. 在不破坏现有聊天功能的前提下，完成新的移动端多模态交互。
4. 将聊天、图片、视频、语音识别、语音合成、声音设计、声音克隆和未来音乐生成统一到同一套产品框架中。
5. 完成真实代码、状态逻辑、接口适配、异常处理和构建验证，不要只输出设计建议。

---

## 二、产品目标

将 SimiChat 重构为一个移动端优先的统一 AI 创作应用。

整体交互方式可以参考现代 OpenAI 类 AI 产品，但不得直接复制其品牌资源、图标、文案或视觉资产。

核心目标：

* 一个应用内完成聊天、图片、视频、语音和音乐创作。
* 所有任务都采用统一的会话式交互。
* 不同任务共用统一的页面框架和结果时间线。
* 底部输入区域根据任务类型动态变化。
* 功能按钮根据当前模型的真实能力动态显示。
* 模型不支持的功能必须直接隐藏，不要显示灰色禁用按钮。
* 移动端优先，同时保持平板和桌面端的响应式兼容。

## 三、硬性原则

### 3.1 不允许根据模型名称硬编码界面

禁止使用以下方式判断功能：

```ts
if (model.includes("tts")) {
  // 显示语音合成
}

if (model.includes("clone")) {
  // 显示声音克隆
}
```

必须建立统一的模型能力配置层，由模型能力决定页面显示内容。

### 3.2 不支持的能力直接隐藏

例如当前聊天模型不支持深入思考和联网搜索：

* 不显示“深入思考”按钮。
* 不显示“小地球”联网搜索按钮。
* 不显示空占位。
* 不显示灰色禁用按钮。
* 请求中不得携带对应参数。

当前模型支持某项能力时，才显示对应入口。

### 3.3 所有结果进入当前会话

以下结果全部写入当前会话时间线：

* 普通文本回复
* 图片生成结果
* 视频生成结果
* TTS 音频结果
* 语音识别结果
* 声音设计结果
* 声音克隆结果
* 音乐生成结果

不要让用户完成任务后跳转到独立测试页面。

### 3.4 用户页面不展示开发调试信息

普通用户界面中不要出现：

* 选择并验证模型
* 刷新模型
* Key 预览
* 复制 cURL
* 连接测试
* 调试请求参数
* 真实 Key 提示

这些功能如现有项目需要保留，应移动到：

```text
设置 → 模型服务 → 连接测试
```

## 四、移动端总体结构

### 4.1 页面框架

移动端页面采用以下结构：

```text
顶部导航栏
模式切换栏
会话内容区
动态底部输入区
```

顶部导航栏包含：

* SimiChat Logo 或产品名称
* 当前会话标题
* 新建会话入口
* 会话列表菜单
* 设置入口

移动端不直接展示桌面端常驻侧边栏。

点击左上角菜单后，打开抽屉式会话列表，展示：

* 新建会话
* 今天
* 昨天
* 更早
* 历史会话
* 设置

### 4.2 一级模式

一级模式固定为：

```text
聊天
图片
视频
语音
```

建议在顶部导航栏下方使用紧凑的分段选择器。

一级模式属于平台能力，因此始终显示。

每个模式内部只展示兼容当前任务的模型。

如果某个模式尚未配置可用模型，展示明确空状态：

```text
当前尚未配置可用的图片生成模型
前往设置添加模型服务
```

不得伪造调用成功。

## 五、聊天模式

### 5.1 页面结构

聊天模式包括：

* 会话消息时间线

* AI 回复
* 流式输出状态
* 消息操作按钮

### 5.2 底部输入区

基础结构：

```text
附件按钮
文本输入框
模型选择器
动态能力按钮
发送按钮
```

基础交互：

* Enter 发送。
* Shift + Enter 换行。
* 支持流式响应。
* 支持停止生成。
* 支持重新生成。
* 支持复制回复。
* 支持继续追问。

### 5.3 附件按钮

只有当前模型支持附件输入时才显示 `+`。

点击后根据模型能力显示对应选项：

```text
上传图片
拍照
上传文件
上传音频
上传视频
```

例如：

* 只支持识图：只显示上传图片和拍照。
* 支持 PDF：增加上传文件。
* 支持音频输入：增加上传音频。
* 不支持任何附件：隐藏 `+`。

上传后的附件显示在输入框上方，支持：

* 缩略图
* 文件名
* 文件大小
* 上传进度
* 删除
* 上传失败重试

### 5.4 深入思考

只有模型能力配置中标记支持推理时才显示。

支持简单开关时：

```text
关闭深入思考
开启深入思考
```

支持推理等级时：

```text
自动
关闭
低
中
高
极高
```

当前状态应以紧凑标签显示在输入区。

切换到不支持推理的模型时：

1. 自动关闭深入思考。
2. 清除请求中的推理参数。
3. 给出轻提示：

```text
当前模型不支持深入思考，已自动关闭
```

### 5.5 联网搜索

只有模型能力配置中标记支持联网搜索时，才显示小地球按钮。

可能的搜索类型包括：

```text
Web 搜索
X 搜索
其他搜索提供方
```

如果只能单选，使用一个菜单。

如果可以同时启用，使用多个独立开关。

切换到不支持联网的模型时：

* 自动关闭搜索。
* 清理搜索参数。
* 隐藏搜索按钮。
* 不向接口继续发送搜索工具字段。

## 十四、模型能力配置层

请建立统一的模型能力描述。

可以根据现有项目结构调整，但功能应至少覆盖以下定义：

```ts
type SimiTaskType =
  | "chat"
  | "image"
  | "video"
  | "tts"
  | "voice_design"
  | "voice_clone"
  | "asr"
  | "music";

interface ModelCapabilityProfile {
  id: string;
  displayName: string;
  providerId?: string;

  taskTypes: SimiTaskType[];

  chat?: {
    reasoning?: {
      supported: boolean;
      levels?: Array<
        "auto" | "off" | "low" | "medium" | "high" | "xhigh"
      >;
    };

    webSearch?: {
      supported: boolean;
      providers?: Array<"web" | "x">;
      multiple?: boolean;
    };

    attachments?: {
      image?: boolean;
      file?: boolean;
      audio?: boolean;
      video?: boolean;
      mimeTypes?: string[];
      maxFileSizeMB?: number;
      maxFiles?: number;
    };
  };

  image?: {
    referenceImage?: boolean;
    imageEdit?: boolean;
    qualities?: string[];
    aspectRatios?: string[];
    resolutions?: string[];
    sizes?: string[];
    maxOutputs?: number;
    customSize?: boolean;
  };

  video?: {
    operations?: Array<"generate" | "edit" | "extend">;
    firstFrame?: boolean;
    lastFrame?: boolean;
    referenceImage?: boolean;
    referenceAudio?: boolean;
    durations?: number[];
    aspectRatios?: string[];
    resolutions?: string[];
  };

  tts?: {
    voices?: string[];
    languages?: string[];
    speeds?: number[];
    formats?: string[];
  };

  voiceDesign?: {
    supported: boolean;
    formats?: string[];
  };

  voiceClone?: {
    supported: boolean;
    referenceMimeTypes?: string[];
    maxReferenceSizeMB?: number;
    formats?: string[];
  };

  asr?: {
    languages?: string[];
    outputFormats?: string[];
    timestamps?: boolean;
    diarization?: boolean;
    punctuation?: boolean;
  };

  music?: {
    durations?: number[];
    styles?: string[];
    vocalModes?: string[];
    formats?: string[];
  };
}
```

优先从后端获取模型能力配置。

如果现有后端暂时没有完整能力字段，可以建立本地模型能力注册表作为兼容层，但：

* 所有能力判断集中管理。
* 不得散落在各页面中。
* 后续可以无痛替换为服务端返回。
* 不得以模型名称字符串匹配作为最终方案。

## 十七、统一任务与结果数据结构

建议建立统一任务对象：

```ts
type TaskStatus =
  | "draft"
  | "uploading"
  | "queued"
  | "running"
  | "streaming"
  | "success"
  | "failed"
  | "cancelled";

interface SimiTask {
  id: string;
  conversationId: string;
  taskType: SimiTaskType;
  modelId: string;
  status: TaskStatus;

  input: {
    text?: string;
    files?: Array<{
      id: string;
      name: string;
      mimeType: string;
      size: number;
      url?: string;
    }>;
  };

  parameters: Record<string, unknown>;

  outputs?: Array<{
    type: "text" | "image" | "video" | "audio" | "transcript";
    url?: string;
    text?: string;
    mimeType?: string;
    duration?: number;
    metadata?: Record<string, unknown>;
  }>;

  error?: {
    code?: string;
    message: string;
  };

  createdAt: string;
  updatedAt: string;
}
```

具体字段可结合现有后端调整，但不同任务必须能统一写入会话时间线。

## 十八、接口适配要求

请先检查现有项目已经支持的接口和协议，不要无必要地重写整个请求层。

建议建立统一 Provider Adapter：

```ts
interface ProviderAdapter {
  chat?: (...args: any[]) => Promise<any>;
  imageGenerate?: (...args: any[]) => Promise<any>;
  videoGenerate?: (...args: any[]) => Promise<any>;
  videoEdit?: (...args: any[]) => Promise<any>;
  videoExtend?: (...args: any[]) => Promise<any>;
  textToSpeech?: (...args: any[]) => Promise<any>;
  voiceDesign?: (...args: any[]) => Promise<any>;
  voiceClone?: (...args: any[]) => Promise<any>;
  speechToText?: (...args: any[]) => Promise<any>;
  musicGenerate?: (...args: any[]) => Promise<any>;
}
```

要求：

* 复用现有 Base URL、API Key 和模型配置。
* API Key 不得出现在前端日志或错误提示中。
* 不同供应商差异封装在适配器内。
* 页面组件不得直接拼接不同供应商请求。
* 请求支持取消。
* 流式请求支持停止。
* 上传任务支持进度显示。
* 失败任务支持重试。
* 错误信息应经过清洗，避免泄露 Key、请求头和内部地址。

如果项目同时支持 OpenAI Chat 和 OpenAI Responses，应复用现有协议选择逻辑。

## 二十三、验收标准

以下条件全部满足才算完成。

### 23.1 聊天能力显示

* 当前模型不支持深入思考时，页面没有深入思考按钮。
* 当前模型不支持联网时，页面没有联网搜索按钮。
* 当前模型不支持附件时，页面没有附件按钮。
* 当前模型支持某项能力时，对应按钮正常出现。
* 切换模型后，能力按钮立即更新。

### 23.2 参数清理

* 切换到不支持联网的模型后，请求中不再发送联网参数。
* 切换到不支持推理的模型后，请求中不再发送推理参数。
* 切换图片模型后，不支持的尺寸、分辨率和数量被自动修正。
* 切换语音模型后，不支持的音色和格式被自动修正。

### 23.3 多模态任务

* 图片可以输入提示词、选择参数并展示结果。
* 视频可以选择生成、编辑或延长，并展示结果。
* 标准 TTS 可以生成并播放音频。
* 声音设计可以输入声音描述。
* 声音克隆必须上传参考音频。
* ASR 可以上传音频或视频并展示转写结果。
* 音乐模式具备完整页面和能力适配结构。

### 23.4 会话统一

* 所有文本、图片、视频、音频和转写结果均出现在当前会话。
* 重新打开历史会话后，可以恢复任务及结果。
* 结果卡片操作方式统一。

### 23.5 移动端

* 360px 至 430px 宽度下无横向滚动。
* 输入区不被软键盘和底部安全区遮挡。
* 参数面板适合单手操作。
* 图片和视频比例正常。
* 会话抽屉和底部抽屉可以正常关闭。

### 23.6 工程质量

* 不新增明显重复代码。
* 不根据模型名称散落硬编码。
* 不在前端暴露完整 API Key。
* 不破坏现有聊天和模型配置。
* 项目能够成功构建。
